# PLI (Pressured Leverage Index) — LI 기반 재정의

`pli-li-dev` 브랜치. PLI를 **승부처(클러치) 감지**에 맞게 **Leverage Index(LI)** 기반으로
재정의한다.

## 왜 바꿨나

기존 PLI는 **승리기대(WE)** 기반이라, 5점차 blowout에서 **리드팀의 평범한 타석을 高로
오탐**했다(예: 리드팀 타자 0.79~0.89). LI는 "**이 타석이 승패를 얼마나 흔드는가(변동성)**"라서
접전·후반·주자만루에서 높고, 승부가 갈린 blowout에서 낮다 — 승부처 알림의 목적에 부합한다.

```
LI = Σ P(결과) × | WP(결과 후 상태) − WP(현재 상태) |  ÷  L_avg
PLI = LI × 압박(Pressure) 가중치
```

## 승률(WP) 모델 — 왜 학습했나

LI는 WP(win probability) 함수가 필요하다. 기존 실측 매트릭스(`data/kbo_we_matrix_filtered.csv`)는
후반/만루 등 **High-Leverage 셀에서 표본 부족으로 노이즈가 심했다**(예: 9말 2사 만루 동점의
홈 승률이 0.088, 7말 만루가 1.0 등 아티팩트). 이런 매트릭스 위에서 LI를 뽑으면 값이 망가진다.

그래서 DB의 **182,994 타석**으로 매끄러운 **로지스틱 WP 모델**을 학습했다.

- 입력: `[inning, half, outs, r1, r2, r3, score_diff]` (홈팀 관점 피처)
- 타깃: 그 경기 홈팀 승리(0/1)
- 결과: logloss 0.6931 → 0.4623, 단조·캘리브레이션 검증 통과
- 산출물: `data/wp_model.json` (raw-space 계수). 의존성 추가 없음(numpy GD).

### 재학습 방법

```bash
docker compose exec web python train_wp_model.py
```
→ `data/wp_model.json` 갱신. pli-api 재시작(또는 --reload)하면 반영된다.
학습 스크립트가 검증 케이스(WP 단조성)도 함께 출력한다.

**주의**: 학습 스크립트의 `make_features` 와 `helpers.py` 의 `_wp_features` 는 **반드시 동일**해야
한다(피처 정의가 어긋나면 WP가 깨진다).

## LI 계산 세부 (helpers.py)

- **결과 확률**(리그평균, per PA): out 0.66 / bb 0.09 / 1b 0.15 / 2b 0.05 / 3b 0.005 / hr 0.045.
  LI는 타자 무관(맥락만)이 정의이므로 상수를 쓴다.
- **전이**(표준 단순): 1루타=주자 한 칸+3루 득점, 2루타=두 칸, 3루타=전원 득점, 홈런=전원+타자,
  볼넷=강제 진루만, 아웃=아웃+1(3아웃 시 다음 half/이닝·주자 리셋). 병살·진루타는 단순화.
- **정규화** `L_avg`: 현실 상태 그리드(1~9회, 양 half, 0~2아웃, 8주자, score_diff −5~5)의
  평균 변동폭 ≈ **0.030** (고전 LI 스케일과 일치). 평균 상황 LI ≈ 1.0.

## 검증

| 상황 | LI |
|---|---|
| 9말 2사 만루 동점(끝내기) | **4.74** |
| 7말 무사 만루 1점뒤 | 3.17 |
| 9말 2사 무주자 동점 | 1.70 |
| 9초 1사 2루 1점차 | 1.36 |
| 1회말 무사 만루 | 0.96 |
| 경기초 무사 무주자 동점 | 0.60 |
| 리드팀 blowout(5점앞) | **0.14** |
| 승부 갈림(5점뒤 9회) | 0.02 |

실경기(HEHH 4회): 리드팀 한화 blowout 국면이 예전 WE기반 0.89 → LI 기반 **0.14**로 정상 하향.

## API 응답 필드

`/calculate_pli_raw_sync`, `/calculate_pli`, 워커 job 결과, 그리고 서빙(`GameRelayView`의
`pli_data`)에 다음이 포함된다:

| 필드 | 의미 |
|---|---|
| `li` | Leverage Index (승부처 지표). **≥ 1.5 → High Leverage** |
| `pli` | LI × 압박가중치 (Pressured LI) |
| `base_we` | 참고용 홈팀 승리기대(학습 WP) |
| `total_weight` | 압박 가중치 곱 |

### 프론트 연동
- `li ≥ 1.5` → "⚡ 승부처입니다!" 알림
- 화면: "현재 타석 LI: 2.42 (High)" — `li` 그대로 표시

## 남은 개선

- **압박(P) 가중치**가 아직 실질 기여가 작다(컨디션 `recent_stats=0`, 날씨 중립 → 대부분 tw=1.0,
  즉 pli ≈ li). `BatterRecent` 등 데이터를 채우면 "LI × 압박"의 압박이 살아난다.
- WP 모델은 로지스틱(선형+엔지니어드 피처). 필요 시 GBM으로 교체 가능(피처 함수만 동일 유지).
